# Sunset-3090-Q：CI 与动态端口修复（2026-10-22）

基于 `6ece562941f31cf54e12c2919f7229cba0af27c1` 和 Actions run `39735705800`。本轮修复仅进入既有私有测试分支；不创建 tag、Release，也不安装或操作 Android 应用。

## CI 失败根因

日志中的 Java 主代码和测试编译已完成，失败发生在 JUnit：

| 失败 | 根因与修复 |
|---|---|
| `AdbWheelBundleTest` 1 项 | Git 不包含真实 wheel 归档；源码 job 排除了资产生成，却要求完整资产测试通过。显式源码模式只在文件确实不存在时跳过，默认完整模式仍失败。 |
| `RuntimeToolsRegistryAndroidTest` 4 项 | 未准备 `prepare-test-runtime` 指针。采用同一显式门禁；存在但损坏、过期、错误摘要的夹具不跳过。APK job 必须先准备当前夹具并实际执行。 |
| `AdbWheelPathsTest` 1 项 | Linux 宿主 `/tmp/...` 被错误当成 Android 外部绑定。容器绝对路径按 rootfs 解析是设计行为。改用 `/storage/...` 外部绑定，并新增 guest `/tmp` 不读写宿主临时目录的正向回归。 |

`dsha.sourceOnlyTests` 默认 `false`，仅接受 `true`/`false`，同时进入 Gradle Test 的任务输入和 JVM 属性，切回完整模式不会复用跳过结果。源码模式最多因缺失外部输入新增 5 项跳过；两版原有 skip 仍独立保留。完整 APK job 无筛选执行两版单测，再逐方法检查这 5 项均恰好执行一次且无失败、错误或跳过。

另修复后续上传错误：固定版本 `upload-artifact` 的 `archive:false` 只能上传单文件并忽略 `name`。APK 改为精确单文件上传，证书、SHA256SUMS、签名与完整测试摘要另行归档。见[固定 action 源码](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/src/upload/upload-artifact.ts)及[CI 契约](ci-test-package.md)。

## 动态端口实现收口

- 原生绑定使用真实 socket 占有端口，按 3090–3099 尝试，仅 `EADDRINUSE` 回退。耗尽与其它绑定错误区分；停止、绑定和端口发布使用同一代次锁，避免已停止的启动线程留下孤立监听。
- `.bridge_port` 发布与读回失败时关闭监听，不能报告 ready；清理走受检文件系统；`/app/version` 增加实际 applicationId。
- 共用 JS 解析器及五份同字节插件副本，每次读取当前端口。严格接受 1–5 位 ASCII 十进制，文件优先、环境变量其次、最后兼容 3090；拒绝高位字节、Unicode 数字、其它进制、空白和超长值。
- JS/Python 读取均有 6 字节上限、NOFOLLOW/NONBLOCK 与文件身份复核，避免检查后替换为 FIFO 卡住，以及非法编码异常。
- 设备引导按每轮提示组装读取端口；状态上报去重包含桥地址。HTTP 401 与旧式 `[UNAUTHORIZED]` 明确映射为授权拒绝；授权事实包含端口，变化后拒绝旧执行，不重放业务。
- launcher 可信目录与每个实际 `dsha-*` 插件目录都部署解析模块；部署目标由注册表回归验证。独立 recovery SDK 保持自己的协议。

## 构建与验收边界

本机为 ARM64，使用 JDK 17、仓库 AIDL shim 和已有 qemu/aapt2 包装完成编译链验证。它不能替代 GitHub x86 runner 的最终全量结果。

原先缺失的 runtime 测试输入已经由锁定 npm 源构建出独立候选；候选归档摘要 `b1de223638f604cf36b719fc32e38fdb74db3851a4420334c9e33996b09387a4`，真实 wheel 则先按已有锁 `173000bd60f8d58f90f988320b9b675540806139da9eae64ea78a0e6ecf5d9d4` 核对。候选只用于隔离测试，不替换既有 APK 固定归档摘要或冒充完整原始输入包。

完整可运行 APK 仍需固定输入包。APK job 先按原 pin 核验输入，再由当前 npm lock 及生成器重建 DSH 归档和实际描述符；原输入包 SHA 与重建运行时 SHA 分别记录，避免旧 recipe 元数据再次触发打包失败。不能仅改 SHA 或跳过校验。双实例/三实例手机验收、完整发布打包和远端 Actions 运行结果均须另记证据。
