# DSHA 0.2.1-rc.3-bxroot.12-dsh0.2.1-rc.3 / build214

- Совместимость путей Termux (движок bxroot): жёстко прописанные пути в скриптах и конфигах для Termux теперь разрешаются в Ubuntu — `/data/data/com.termux/files/usr` → `/usr` (`tmp`/`etc`/`var` → `/tmp`/`/etc`/`/var`), `/data/data/com.termux/files/home` → `/root`, форма `/data/user/0/...` тоже работает, поэтому shebang `#!/data/data/com.termux/files/usr/bin/bash` запускается. `PREFIX`/`TERMUX_VERSION` не задаются; `pkg`, bionic-программы Termux и приложения-компаньоны вроде Termux:X11 по-прежнему не поддерживаются. Отключение: `BXROOT_NO_TERMUX_COMPAT=1`.
- Запуск ещё быстрее: контейнерный процесс «миграции старых меток проверки» больше не запускается, если таких меток нет (около 0,5 с); DSH использует кеш компиляции модулей Node (`/root/.cache/dsha-node-compile`, автоматически сбрасывается при изменении исходников; отключается `NODE_DISABLE_COMPILE_CACHE=1`), что сокращает разбор и компиляцию ~180 пакетов при каждом запуске.
- Ускорена первая распаковка: новая среда больше не сбрасывает на диск каждый файл по отдельности (около 80 000 вызовов fsync), а синхронизирует всё один раз в конце. Включено только на ядрах Linux 5.8+; ошибки записи по-прежнему обнаруживаются, а при отключении питания кандидат отбрасывается и распаковывается заново, не затрагивая опубликованную среду.
- Ускорен запуск: результат подготовки терминала/Web кешируется между перезапусками приложения. Если APK, среда и управляемые файлы не изменились, первый терминал после холодного старта больше не сравнивает побайтно 103 встроенных файла и не прогоняет цепочку патчей; любое изменение управляемого файла снова запускает полную подготовку.
- Новые команды нативных возможностей: в Ubuntu доступны команды в стиле Termux:API — `termux-clipboard-get/set`, `termux-notification`, `termux-toast`, `termux-vibrate`, `termux-torch`, `termux-open-url`, `termux-share`, `termux-location`, `termux-sensor`, `termux-battery-status`, `termux-dialog`; `dsha-am start/broadcast` запускает экраны и отправляет широковещательные сообщения от имени DSHA (без root, с подтверждением по политике экрана); `dsha-su` выполняет любые команды через разрешённый root или Shizuku после включения «Неограниченной оболочки устройства» в Настройки → Разрешения устройства (по умолчанию выключено; разделы/SELinux/монтирование/прошивка по-прежнему запрещены, ADB сохраняет список разрешённых).
- - Добавлены нативные вызовы в стиле Termux (движок bxroot): из Ubuntu можно напрямую запускать нативные команды Android (`getprop`, `toybox`, `pm` и др.; одноимённая программа guest имеет приоритет, либо явно `bx-host <команда>`), а нативный shell Android может вернуться в тот же сеанс Ubuntu через `$BXROOT_ENTER`. UID остаётся UID приложения, без повышения прав; доступность системных команд определяют разрешения Android.
- - Исправлено: на системах вроде HyperOS крошечные (1×1) системные окна-глифы/значки (HyperDuo glyph, значок заметок и т.п.) вызывали TARGET_WINDOW_OCCLUDED и делали координатные нажатия и свайпы полностью неработоспособными. Окна пренебрежимо малой площади больше не участвуют в решении о заслонении (#212).
- - Когда остановка приложения блокируется сообщением «формат списка приложений не подтверждён», ошибка теперь содержит первую неожиданную строку (замаскированную, усечённую) и указывает пользовательский или системный список — это помогает выявить различия вывода pm в конкретных ROM (#210, продолжение).
- - Сохранены dsh-web-mobile 3.2.2, DSH rc.3, локальный доступ и доступ по LAN, а также десять языков. Проверка на телефоне остаётся приостановленной.
