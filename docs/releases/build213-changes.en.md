# DSHA 0.2.1-rc.3-bxroot.11-dsh0.2.1-rc.3 / build213

- Faster startup again: the "migrate legacy review markers" container process is no longer started when no such markers exist (about 0.5 s); DSH now uses the Node module compile cache (`/root/.cache/dsha-node-compile`, invalidated automatically when sources change; set `NODE_DISABLE_COMPILE_CACHE=1` to turn it off), cutting parse/compile time for the ~180 packages imported at each start.
- Faster first extraction: a fresh environment no longer forces every file to disk individually (about 80,000 fsync calls); it syncs once at the end instead. Enabled only on Linux 5.8+ kernels; write errors are still detected, and a power loss mid-way discards the candidate and re-extracts without touching the published environment.
- Faster startup: the terminal/Web runtime preparation result is cached across app restarts. When the APK, environment and managed files are unchanged, the first terminal after a cold start no longer re-compares 103 bundled files byte by byte or re-runs the patch chain; any change to a managed file triggers full preparation again.
- New native capability commands: Termux:API-style `termux-clipboard-get/set`, `termux-notification`, `termux-toast`, `termux-vibrate`, `termux-torch`, `termux-open-url`, `termux-share`, `termux-location`, `termux-sensor`, `termux-battery-status` and `termux-dialog` work directly in Ubuntu; `dsha-am start/broadcast` starts activities or sends broadcasts as DSHA itself (no root, asks according to the screen confirmation policy); `dsha-su` runs any command through the authorized root or Shizuku channel once "Unrestricted device shell" is enabled in Settings → Device permissions (off by default; partition/SELinux/mount/flash stay blocked and ADB keeps its allowlist).
- - Added Termux-like native calls (bxroot engine): Ubuntu can run Android native commands directly (`getprop`, `toybox`, `pm`, …; same-named guest programs win, or use `bx-host <command>` explicitly), and an Android native shell can return to the same Ubuntu session via `$BXROOT_ENTER`. Commands keep this app's UID with no privilege gain; which system commands work is decided by Android permissions.
- - Fixed 1×1 system glyph/badge windows (HyperDuo glyph, notes badge, etc.) on HyperOS-like systems triggering TARGET_WINDOW_OCCLUDED and making coordinate taps and swipes entirely unusable: windows of negligible area no longer participate in the occlusion decision (#212).
- - When stopping an app is blocked by "app list format could not be verified", the error now carries the first unexpected line (redacted, truncated) and names the user/system list, helping pinpoint ROM-specific pm output differences (#210 follow-up).
- - Retain dsh-web-mobile 3.2.2, DSH rc.3, local and LAN access, and ten languages. Phone acceptance remains paused.
