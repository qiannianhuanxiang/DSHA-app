# DSHA 0.2.1-rc.3-bxroot.9 / build211：原生能力命令

日期：2026-11-01（UTC）。包名 `dsh.android.bxroot`，独立测试签名（证书 SHA-256 `e4e77d8c…e3e31c`，非 E7E3），Standard。

## 变化

1. **Termux:API 风格命令**（`/root/dsh-bin`，所有引擎）：`termux-clipboard-get/set`、`termux-notification`、`termux-toast`、`termux-vibrate`、`termux-torch`、`termux-open-url`、`termux-share`、`termux-location`、`termux-sensor`、`termux-battery-status`、`termux-dialog`、`termux-wake-lock/unlock`、`termux-info`。全部是 `/root/.dsh/dsha-native.py` 对既有 `/app/*` 端点的薄封装，不新增权限；能力关闭时照原样返回 `DISABLED`/`NO_PERMISSION` 并以非零退出。
2. **以 DSHA 身份发 Intent**：新端点 `/app/intent`（`cmd` 为 am 风格参数）与 guest 命令 `dsha-am`。只支持 `start`（`-n 包名/.类` 或 `-p 包名 -a ACTION`）和 `broadcast`（必须带 `-p` 或 `-n`）；`-d` 只收 http(s)/geo/tel/mailto/market；未知选项（`-W`、`--user`、`--ez` 等）明确拒绝。授权复用 `/app/launch` 的屏幕确认、敏感应用与能力代理（CapabilityBroker）流程，解析在 `util/IntentRequest`，发送在 `bridge/AppIntentDispatch`。
3. **不受限制的设备 shell**（默认关闭）：设置 → 设备能力授权新增开关，开启需二次确认。`/device/execute?unrestricted=1`（guest `dsha-su`）把命令交给已授权 root（优先）或 Shizuku 的 `sh -c`；ADB 不提供该模式。硬禁止项（分区、SELinux、setprop、挂载、重启、刷机）由 `DeviceShellPolicy.inspectUnrestricted` 在 App 侧与特权进程内（`ShellService.execUnrestricted`）各拒绝一次。开关存于 `dsha_device_grants`，与短信、全局屏幕放行独立。
4. 系统提示（`dsh-device-shell-guide` v4）：已安装原生命令时追加用法段；bxroot 原生通道中“白名单外命令”改为指向 `dsha-am` / `/app/ui/*` / `dsha-su`。`/app/help` 同步。
5. `dsha-am` / `dsha-su` 先查 `/app/version` 的 `APP_CODE ≥ 211`：旧 DSHA 对 `/app/intent` 回 `[NO_CMD]`、对 `unrestricted=1` 会静默按白名单执行，必须先拒绝而不是报成功。
