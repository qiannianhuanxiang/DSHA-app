# DSHA 0.2.1-rc.3-bxroot.11-dsh0.2.1-rc.3 / build213

- Démarrage encore plus rapide : le processus de conteneur « migrer les anciens marqueurs de revue » n'est plus lancé quand aucun marqueur n'existe (environ 0,5 s) ; DSH utilise désormais le cache de compilation des modules Node (`/root/.cache/dsha-node-compile`, invalidé automatiquement quand les sources changent ; `NODE_DISABLE_COMPILE_CACHE=1` le désactive), réduisant le temps d'analyse/compilation des ~180 paquets importés à chaque démarrage.
- Première extraction plus rapide : un nouvel environnement n'écrit plus chaque fichier de force sur le disque un par un (environ 80 000 appels fsync) et se synchronise une seule fois à la fin. Activé uniquement sur les noyaux Linux 5.8+ ; les erreurs d'écriture restent détectées, et une coupure de courant en cours de route abandonne le candidat et relance l'extraction sans toucher à l'environnement publié.
- Démarrage plus rapide : le résultat de préparation du terminal/Web est mis en cache entre les redémarrages de l'app. Si l'APK, l'environnement et les fichiers gérés n'ont pas changé, le premier terminal après un démarrage à froid ne recompare plus octet par octet les 103 fichiers intégrés ni ne relance la chaîne de correctifs ; toute modification d'un fichier géré déclenche à nouveau la préparation complète.
- Nouvelles commandes de capacités natives : dans Ubuntu, les commandes de style Termux:API `termux-clipboard-get/set`, `termux-notification`, `termux-toast`, `termux-vibrate`, `termux-torch`, `termux-open-url`, `termux-share`, `termux-location`, `termux-sensor`, `termux-battery-status` et `termux-dialog` fonctionnent directement ; `dsha-am start/broadcast` ouvre des écrans ou envoie des diffusions au nom de DSHA (sans root, avec confirmation selon la politique d’écran) ; `dsha-su` exécute n’importe quelle commande via le root ou Shizuku autorisé une fois le « Shell de l’appareil sans restriction » activé dans Paramètres → Autorisations de l’appareil (désactivé par défaut ; partition/SELinux/montage/flashage restent bloqués et l’ADB conserve sa liste d’autorisations).
- - Ajout d’appels natifs façon Termux (moteur bxroot) : Ubuntu peut lancer directement les commandes natives Android (`getprop`, `toybox`, `pm`, … ; un programme guest du même nom reste prioritaire, ou `bx-host <commande>` explicitement), et un shell Android natif peut revenir dans la même session Ubuntu via `$BXROOT_ENTER`. L’UID reste celui de l’application, sans élévation ; les commandes système utilisables dépendent des permissions Android.
- - Correction du problème où des fenêtre système minuscule 1×1 — glyphes HyperDuo, badge de notes, etc. — déclenchaient TARGET_WINDOW_OCCLUDED sur les systèmes de type HyperOS, rendant tap et swipe par coordonnées totalement inutilisables : les fenêtres d’une aire négligeable ne participent plus à la décision d’occlusion (#212).
- - Lorsque l’arrêt d’une application est bloqué par « format de la liste d’applications non vérifiable », l’erreur embarque désormais la première ligne inattendue (masquée, tronquée) et précise la liste utilisateur ou système, afin de cerner les différences de sortie pm propres à chaque ROM (#210 complément).
- - Conserver dsh-web-mobile 3.2.2, DSH rc.3, l’accès local et réseau local et les dix langues. La validation sur téléphone reste suspendue.
